Events
This lesson does not introduce addEventListener - you have used it since lesson 4. Here we go deeper: the event object, keyboard and input events, and how to listen on many elements at once. What is an event An *event* is something that happens in the page: the user clicks, types a letter, moves the mouse, chooses an option, sends a form. Your program does not "wait" for these things. Instead you say: *"when this happens, run this function"*. Then the browser calls your function at the right moment. You already did this with `click` in lesson 4; now we open the box. The events you will use
  • `click` — the user clicks the element.
  • `input` — the user types *one* character in a field.
  • `change` — the user leaves the field, or picks an option in a `<select>`.
  • `keydown` — the user presses a key.
  • `submit` — a form is sent (lesson 12).
  • `mouseover` / `mouseout` — the mouse enters / leaves the element.
    •      The event object The browser gives your function an object with information about what happened: button.addEventListener("click", function (event) { console.log(event.type); // "click" console.log(event.target); // the element that was clicked }); The two you really need: `event.target` (which element fired it) and `event.preventDefault()` (stop the normal behaviour — we use it with forms in lesson 12). Events on inputs const input = document.querySelector("#nameInput"); const output = document.querySelector("#output"); // input: fires on every key input.addEventListener("input", function () { output.textContent = `Hello, ${input.value}`; }); // change: fires when the user leaves the field or chooses an option input.addEventListener("change", function () { output.textContent = `Final value: ${input.value}`; }); `input` is what makes a page feel alive: a live search, a character counter, a preview that updates as you type. Keyboard events input.addEventListener("keydown", function (event) { if (event.key === "Enter") { addItem(); } }); `event.key` gives the key as text: `"Enter"`, `"Escape"`, `"a"`, `"ArrowUp"`. Adding "and Enter also works" to a field takes three lines and makes your app feel professional. Many elements at once const buttons = document.querySelectorAll(".colour-button"); for (const button of buttons) { button.addEventListener("click", function (event) { document.body.style.backgroundColor = event.target.dataset.colour; }); } <button class="colour-button" data-colour="red">Red</button> <button class="colour-button" data-colour="green">Green</button> <button class="colour-button" data-colour="blue">Blue</button> One loop, one listener for each button. Inside, `event.target` tells you which one was clicked, and `dataset` reads any attribute that starts with `data-`. That is how you carry information from the HTML to your code without abusing the text of the button. Removing a listener function sayHello() { output.textContent = "Hello!"; } button.addEventListener("click", sayHello); button.removeEventListener("click", sayHello); // only works with a NAMED function This only works if the function has a name. It is one more reason to prefer named functions over anonymous ones. Common mistakes // 1. Brackets: runs it now, listens for nothing button.addEventListener("click", sayHello()); // WRONG button.addEventListener("click", sayHello); // right // 2. Adding the listener inside another listener // -> every click adds one more, and the function runs 2, 3, 4 times. // Put your addEventListener at the top level, once. // 3. Listening on an element that does not exist yet // -> if you create a button from JavaScript, add its listener // right after you create it (lesson 11).
